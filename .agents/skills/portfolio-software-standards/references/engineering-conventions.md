# 포트폴리오 소프트웨어 엔지니어링 규칙

## 1. 한글 주석과 문서화

- 모든 모듈은 파일 상단 또는 진입점 근처에 책임과 외부 의존성을 설명한다.
- 모든 클래스는 책임, 생성·소멸 시점, 소유하는 상태를 한글로 설명한다.
- 모든 공개 메서드와 함수는 목적, 중요한 입력·출력, 부작용, 발생 가능한 오류를 한글로 설명한다.
- 짧은 내부 함수도 이름만으로 의도가 충분히 드러나지 않으면 한 줄 한글 주석을 둔다.
- 이벤트 처리, 비동기 흐름, 캐시, 재시도, 애니메이션, 반응형 분기, 접근성 보정에는 `무엇`보다 `왜`를 남긴다.
- HTML의 큰 영역과 CSS 컴포넌트 묶음에는 탐색용 한글 구분 주석을 둔다.
- 단순 대입·반환·반복문을 줄마다 번역하는 주석은 쓰지 않는다.
- 동작이 바뀌면 관련 주석, 테스트 설명, 문서도 같은 변경에서 갱신한다.

JavaScript 예시:

```js
/**
 * 섹션 전환을 한 곳에서 제어해 중복 애니메이션과 포커스 유실을 막는다.
 * @param {number} nextSectionIndex 이동할 섹션의 0 기반 인덱스
 */
function navigateToSection(nextSectionIndex) {
  // ...
}
```

Python 예시:

```python
def load_portfolio_entries(source_path: Path) -> list[PortfolioEntry]:
    """원본 파일을 검증해 화면에서 사용할 포트폴리오 항목으로 변환한다."""
```

## 2. 이름 규칙

공통 원칙:

- 이름은 구현 방식보다 도메인 의미와 역할을 표현한다.
- 한 개념에는 한 용어만 쓴다. `section`, `chapter`, `page`를 같은 뜻으로 섞지 않는다.
- 불리언은 질문처럼 읽히게 짓고, 컬렉션은 복수형을 사용한다.
- 단위가 중요하면 이름에 단위를 붙인다. 예: `durationMs`, `widthPx`.
- `data`, `item`, `temp`, `value`, `manager`, `util` 같은 넓은 이름은 작은 지역 범위를 제외하면 피한다.
- 숫자 접미사 대신 역할을 쓴다. `button2` 대신 `nextButton`을 쓴다.

JavaScript·TypeScript:

| 대상 | 규칙 | 예시 |
| --- | --- | --- |
| 변수·매개변수 | `camelCase` | `activeSectionIndex` |
| 함수·메서드 | 동사형 `camelCase` | `updateDeckPosition` |
| 이벤트 처리 | `handle` + 대상/동작 | `handleDialogClose` |
| 불리언 | `is`, `has`, `can`, `should` | `isMoving` |
| 클래스 | 명사형 `PascalCase` | `SceneController` |
| 전역 불변 상수 | `UPPER_SNAKE_CASE` | `MAX_RETRY_COUNT` |
| DOM 참조 | 역할 + `Element` 또는 복수형 | `dialogElement`, `sectionCards` |

Python:

| 대상 | 규칙 | 예시 |
| --- | --- | --- |
| 변수·함수·모듈 | `snake_case` | `load_portfolio_entries` |
| 클래스 | `PascalCase` | `PortfolioRepository` |
| 상수 | `UPPER_SNAKE_CASE` | `REQUEST_TIMEOUT_SECONDS` |
| 내부 구현 | 필요한 경우 앞에 `_` | `_parse_source_row` |

HTML·CSS·파일:

- HTML `id`, CSS 클래스, CSS 변수, 일반 웹 파일 이름은 소문자 `kebab-case`를 사용한다.
- CSS 클래스는 모양이 아니라 역할을 표현한다. `.blue-box`보다 `.project-card`를 쓴다.
- 상태 클래스는 `is-active`, `is-open`, `has-error`처럼 상태임을 드러낸다.
- 테스트 파일은 대상 파일과 대응되는 이름을 사용한다.
- 외부 API, 저장 형식, 기존 DOM 계약과 연결된 이름은 호환성을 먼저 검토한다.

## 3. 모듈과 의존성

- 프론트 소스는 `frontend/`, 서버 소스는 `backend/`, 공유 정적 자산은 `assets/`, 자동화는 `scripts/`에 둔다.
- 생성물 `dist/`를 직접 수정하지 않는다.
- UI, 도메인 규칙, 데이터 접근, 외부 I/O를 가능한 한 분리한다.
- 상위 정책이 하위 구현 세부사항을 직접 알지 않도록 의존성을 좁은 함수나 인터페이스로 전달한다.
- 순환 의존성을 만들지 않는다. 새 모듈을 만들기 전에 기존 모듈의 책임을 확장하는 편이 자연스러운지 검토한다.
- 세 곳 이상에서 같은 규칙이 반복되거나 함께 바뀌어야 할 때만 공통화를 우선 검토한다.
- 단순한 흐름을 유지한다. 미래 가능성만을 위한 추상 계층, 설정, 플러그인 구조는 만들지 않는다.

## 4. 함수·클래스 설계

- 함수는 하나의 사용자 행동, 계산, 또는 상태 전환을 책임진다.
- 계산과 I/O를 분리해 핵심 규칙을 독립적으로 테스트할 수 있게 한다.
- 매개변수가 많아지면 관련 값의 응집도를 확인하되, 의미 없는 옵션 객체로 숨기지 않는다.
- 숨은 전역 상태를 늘리지 않는다. 함께 움직이는 상태는 한 객체나 컨트롤러가 소유한다.
- 클래스는 실제 상태와 불변식을 함께 관리할 때 사용한다. 함수 묶음을 위한 빈 클래스는 만들지 않는다.
- 조기 반환으로 예외 흐름을 분리하고, 깊은 중첩을 피한다.
- 마법 숫자와 문자열은 디자인 토큰, 설정, 또는 이름 있는 상수로 승격한다.

## 5. 오류·보안·관찰 가능성

- 입력은 시스템 경계에서 검증하고, 내부 함수는 검증된 형태를 받게 한다.
- 오류를 삼키지 않는다. 사용자가 취할 수 있는 조치와 개발자가 추적할 문맥을 구분해 제공한다.
- 재시도는 일시적 실패에만 제한하고 최대 횟수와 중단 조건을 둔다.
- 로그에 비밀번호, 토큰, 개인식별정보, 원문 민감 데이터를 남기지 않는다.
- 비밀값과 환경별 주소를 소스에 하드코딩하지 않는다.
- HTML 삽입, URL, 파일 경로, 외부 응답은 신뢰 경계를 고려해 이스케이프·검증한다.

## 6. 프론트엔드와 디자인

- 기존 색상, 타이포그래피, 간격 토큰과 반응형 중단점을 먼저 재사용한다.
- 카드 안쪽 여백은 `--card-padding`, 열 간격은 `--layout-gap`, 섹션 간격은 `--section-gap`, 행 간격은 `--row-space`, 패널 여백은 `--panel-padding`을 우선한다.
- 섹션별 임의 `max-width`로 공통 정렬축을 깨지 않는다.
- 시맨틱 HTML, 키보드 조작, 보이는 포커스, 최소 44px 주요 조작 영역을 유지한다.
- PC 한 화면 한 카드 구성을 지키고, 1920×1080과 1366×768에서 잘림·쏠림을 확인한다.
- 모바일에서는 중요도 순으로 열을 쌓고 가로 스크롤, 겹침, 잘린 텍스트가 없는지 확인한다.
- 모션 종료 뒤 잔여 `transform`, `clip-path`, `opacity`, `inert` 상태가 읽기와 포커스를 막지 않게 한다.

## 7. 테스트와 변경 관리

- 테스트는 내부 구현 문구보다 사용자가 관찰할 행동과 중요한 불변식을 검증한다.
- 버그 수정에는 가능하면 실패를 재현하는 회귀 테스트를 먼저 또는 함께 추가한다.
- 정상 경로, 경계값, 실패 경로 가운데 변경 위험에 맞는 범위를 검증한다.
- 리팩터링과 기능 변경이 큰 경우 분리 가능한 단위로 나누되, 사용자에게 불완전한 중간 상태를 남기지 않는다.
- 공개 인터페이스, 폴더 구조, 빌드 방식, 운영 규칙을 바꾸면 관련 문서를 갱신한다.
- 관련 없는 파일의 이름 변경, 포맷 전면 수정, 대규모 재배치는 피한다.

## 8. 완료 기준

- 요청한 동작이 소스와 생성 결과물에 반영됐다.
- 새 코드의 주석과 이름이 이 규칙을 따른다.
- 중복, 숨은 상태, 불필요한 결합이 늘지 않았다.
- 오류와 빈 상태가 안전하게 처리된다.
- 관련 테스트와 문서가 갱신됐다.
- 프로젝트의 빌드, 정적 검사, 테스트가 통과한다.
- 실행하지 못한 시각·통합·외부 시스템 검증은 완료한 것처럼 표현하지 않는다.
